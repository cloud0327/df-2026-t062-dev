# ベンチマーク（アセスメントを正しく書けているか）

AI が原本（会話の記録など）から事実を取り出し（2 層目）、アセスメントシート（3 層目）を書いた結果を、人が作った正解と比べて採点する。

- 評価の考え方: [`../scenario/README.md`](../scenario/README.md) の「確かめ方」。**シート（3 層目）が主**。事実（2 層目）は、どこで落ちたかを見分けるのに使う。
- 3 層のデータの形: [`../データの定義.md`](../データの定義.md) の「利用者のデータの 3 層」。
- 今の正解: [`../scenario/gold/`](../scenario/gold/)（演習シナリオの 1 回目のあと・2 回目のあと）。

## ファイル

| ファイル | 中身 |
|---|---|
| `bench.py` | 採点の本体。`score`（採点）・`check-gold`（正解の書き間違いを確かめる）・`show-gold`（人が確かめる正解シートを作る）・`gold-data`（正解のシートを用紙に印字するデータにする） |
| `judge.py` | 意味の判定（文章に要点が書かれているか、根拠にない中身がないか、同じ事実か）。判定は `judgments.json` に貯めて使い回す |
| `test_bench.py` | テスト。`python3 -m unittest discover -s eval/bench -v` |

Python 3.10 以上。標準ライブラリだけで動く（Claude に判定させるときだけ `anthropic` が要る）。

## 使い方

```sh
# 正解の書き間違いを確かめる（欄の名前、選択肢、原本の id、事実の id、同じ欄の正解が 2 つないか）
python3 eval/bench/bench.py check-gold --gold eval/scenario/gold

# 人が確かめるための正解シート（正解シート_v1.md / _v2.md）を作る
python3 eval/bench/bench.py show-gold --gold eval/scenario/gold

# 正解のシートを、用紙に印字するデータ（アセスメント_v1.json / _v2.json）にする。PDF にするのは forms/scripts/generate.mjs
python3 eval/bench/bench.py gold-data --gold eval/scenario/gold --out eval/scenario/gold/用紙

# 採点する。結果は <提出>/bench/report.md と result.json
python3 eval/bench/bench.py score --gold eval/scenario/gold --submission <提出のフォルダ>
```

### 意味の判定（`--judge`）

文章の欄と事実の照合は、文字の一致では決められないので、判定役に聞く。

| `--judge` | 動き |
|---|---|
| `cache`（既定） | **外のサービスに何も送らない。** 答えのない問いは `eval/scenario/judgments.json` に `"answer": null` で書き出し、「要判定（判定待ち）」として数える。人（または Claude Code）が answer を書き込めば、次の実行から使われる |
| `anthropic` | Claude（既定 `claude-opus-5-5`、`BENCH_JUDGE_MODEL` で変更可）に判定させ、答えを `judgments.json` に貯める。`pip install anthropic` と認証（`ANTHROPIC_API_KEY` か `ant auth login`）が要る。安全のための拒否が起きたときにサーバー側で別のモデルに回す設定（`fallbacks: "default"`）を入れてある。**公開・架空のデータ（このシナリオなど）にだけ使う。** 本物の面談の記録は外に送らない（プロジェクトの決まり） |

`anthropic` はまだ実際に動かしていない（2026-11-08 時点で、このマシンに SDK も認証もない）。

answer の形:

| 問い（`task.kind`） | answer |
|---|---|
| `points`（文章に要点が書かれているか） | `{"covered": [true, false, …]}`（要点と同じ順） |
| `unsupported`（根拠にない中身） | `{"claims": ["根拠にない文", …]}`（なければ `[]`） |
| `match`（同じことを述べている候補） | `{"match": "候補の id"}`（なければ `null`） |

## 提出の形（AI の出力）

時点ごとにフォルダを分ける。

```
<提出>/
  v1/  facts.json  questions.json  sheet.json   ← 1 回目の面談のあと
  v2/  facts.json  questions.json  sheet.json   ← 2 回目のあと
```

- `facts.json`: `{"facts": [{"id": "f-1", "text": "咀嚼に大きな問題はない", "item23": 19, "who": "ST", "kind": "said", "from": ["s2-031"]}, …]}`（2 層目の形）
- `questions.json`: `{"questions": [{"id": "q-1", "text": "自宅の段差", "item23": 22, "why": "later", "from": ["s2-025"], "status": "open"}, …]}`
- `sheet.json`: `{"fields": {"meal.chewing": {"value": "問題なし", "by": "ai", "facts": ["f-1"]}, …}, "unplaced": ["f-7"]}`（採点に使うのは `value` と `facts` だけ）
  - `fields` は 3 層目の形。まとまりの欄（object）は `value` に `{"has": true, "detail": "…"}`、繰り返しの欄（list）は `value` に行の配列を入れる。
  - `unplaced` は「入れる欄がない」と判断した事実の id。

## 正解の形（`gold/`）

| ファイル | 中身 |
|---|---|
| `facts.json` | 正解の事実（2 層目と同じ形）。`from` で、何回目から分かる事実かが決まる |
| `questions.json` | 正解の「確かめること」。`closedBy` の事実が分かった時点で閉じる |
| `sheet.json` | 正解のシート。下の形 |

`sheet.json` の `entries` の 1 つ 1 つ:

```json
{"key": "meal.chewing", "expect": "問題なし", "from": ["s2-031"]}
{"key": "survey.2_2", "anyOf": ["介助されていない", "見守り等"], "from": ["s2-011"], "note": "要確認"}
{"key": "communication.speechDisorder", "sub": "has", "expect": true, "from": ["s2-031"]}
{"key": "notes.meal", "points": [{"text": "毎食ほぼ全量食べている", "from": ["s2-013"]}, …]}
{"key": "family.members", "items": [{"match": {"relationship": "子の配偶者"}, "from": ["s2-059"],
                                     "subs": {"isMainCaregiver": {"expect": true}}}]}
```

**決まり: 話に出たこと（根拠の発言があること）は書く。出ていないことは書かない（entries に入れない）。** 「空でもよい」という正解は使わない。`anyOf` に `null` を入れたり `allowEmpty` を書いたりすると、`check-gold` が間違いとして止める。

- 理由: 「空でもよい」を入れた叩き台では、何も書かない提出が書くべき欄の 52% で「正しい」になった（2026-11-08 に確かめた）。それでは点数が意味を持たない。
- 推測でしか埋まらない欄（話に出ていない聴力、4 群の「ない」など）は、空が正しい。AI はそこを「確かめること」として次の面談で聞く。
- 同じ話は 2 つの文章の欄に書かない（置き場所の決まりは [`../scenario/README.md`](../scenario/README.md)）。今の採点は、提出が同じ話を 2 か所に書いても減点しない（根拠のある中身なので「作り話」にならない）。

| 書き方 | 意味 |
|---|---|
| `expect` | 正しい値は 1 つ |
| `anyOf` | 話から言える値が 2 つ以上あり、どちらとも決められない。`note` に理由を書く |
| `points` | 文章の欄。入っているべき要点を並べる |
| `sub` | まとまりの欄の中の項目 |
| `items` | 繰り返しの欄の行。`match` の項目でどの行かを決め（選ぶ項目は値の一致、文字の項目は判定役）、`subs` に行の中の正解を書く |
| `from` | 根拠の発言・記録の id。**ここから、何回目からの正解かが決まる**（いちばん早い回から）。回で正解が変わるときは `at: ["v2"]` のように分けて書く |
| `facts` | 元になる正解の事実の id。書かなければ、`from` が重なり 23 項目の番号が同じ事実を使う（どこで落ちたかの見分けに使う） |

**`entries` に書いていない欄は、空のままが正しい。** 必須の欄でも、話に出てこなければ空が正しい。

### 採点の仕組みの確かめ（2026-11-08）

今の正解（`eval/scenario/gold/`）に対して、2 つの提出を採点した。

| 提出 | 1 回目のあと | 2 回目のあと |
|---|---|---|
| 正解をそのまま写したもの（判定役は何でも通す） | 書くべき欄 81/81 正しい、作り話 0、事実 134/134 | 83/83、作り話 0、事実 140/140、確かめること 3/3 閉じた |
| 何も書かないもの | 書くべき欄 0/81、空のはずの欄 377/377 空で正しい | 0/83、375/375 |

## 判定

採点の単位は欄（まとまりの欄は中の項目ごと、繰り返しの欄は行の中の項目ごと）。図の欄は採点しない。

| 判定 | 意味 |
|---|---|
| 正しい | 正解と同じ値・中身で、根拠の事実が正解の根拠の発言を指している |
| 根拠違い | 値は正しいが、根拠の事実がない、正解の根拠と違う発言を指している、またはまだ聞いていない回の発言を指している |
| 誤り | 書いたが値が違う |
| 抜け | 書くべきなのに空。文章の欄で、要点が 1 つも入っていない |
| 一部抜け | 文章の欄で、要点の一部しか入っていない |
| 作り話 | 空のはずの欄に値を書いた。または文章に、根拠にない中身がある |
| 余分 | 空のはずの文章の欄に、根拠のある中身を書いた（作り話ではないが、置き場所が正解と違う） |
| 空で正しい | 空のはずの欄が空 |
| 要判定 | 判定役の答えがまだない |

- 比べるときは、全角・半角の違いと空白を無視する。複数選択は順番を問わない。真偽の `false` は「空」ではなく「いいえ」という値として扱う。
- 結果は「書くべき欄」と「空のはずの欄」に分けて数える。空のはずの欄を「正しい」に混ぜると、成績が良く見えすぎるため。

### どこで落ちたか（誤り・抜け・一部抜けのとき）

| 正解の事実が提出の事実（2 層目）に | 原因 |
|---|---|
| ない | 取り出し（原本 → 事実） |
| ある | 書く段階（事実 → シート）。番号の付け間違いがあれば「（番号違い）」 |

提出の事実が正解の事実と同じかは、原本の同じ発言を指している事実の中から、判定役が選ぶ。

あわせて、提出の事実のうち、シートのどこにも使われず `unplaced` にもないもの（宙に浮いた事実）を数える。
