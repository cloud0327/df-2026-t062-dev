# テスト用シナリオ：演習シナリオ「アセスメント面接の場面」

AI 業務エージェントが、面談の記録からアセスメントシートを正しく書けるかを確かめるための入力。2026-11-08 にユーザーがネットで見つけ、使うことに決めた。

- 出典: 山梨県介護支援専門員協会が公開している演習用の PDF（https://yamanashi-cma.com/files/3116/4065/5971/1.pdf）。2026-11-08 にダウンロードした（PDF の作成日は 2021-12-28）。
- 人物（本人の甲斐さん、長男の雅史さん、長男の嫁の春子さん、ケアマネの加藤さん）はすべて架空。個人情報ではない。
- 使い方: チーム内のテストに使う。デモなど外に見せるときは出典を示すか、協会に確かめる（まだ確かめていない）。

## 正解の叩き台（2026-11-08、Claude が作成）

| ファイル | 中身 | 数 |
|---|---|---|
| `gold/facts.json` | 正解の事実（2 層目）。1 件 = 1 つの事実、23 項目の番号つき | 1 回目のあと 134、2 回目のあと 140 |
| `gold/questions.json` | 正解の「確かめること」。あとで確かめると言われたもの 3（段差、入浴の方法、自宅での動き方。どれも家屋調査で閉じる）、推測できるが言われていないもの 3（倒れる前の世帯、仕事の内容、娘と孫の暮らし） | 6 |
| `gold/sheet.json` | 正解のシート（3 層目）。書いていない欄は空が正しい | 書くべき項目 1 回目 81、2 回目 83 |

**決まり**: 話に出たこと（根拠の発言があること）は書く。出ていないことは書かない。推測で埋めない。「空でもよい」という正解は使わない（何も書かない提出の点数が上がってしまうため）。

**同じ話を 2 つの文章の欄に書かない**（2026-11-08、ユーザーの指示。似ている程度はよい）。1 つの事実は、次の決まりで 1 つの欄に寄せる。

| 話の種類 | 書く欄 | 書かない欄 |
|---|---|---|
| 本人・家族の思い・希望・不安（全体に関わるもの。暮らしや役割への希望も。例: 嫁の「また無尽に行けるように」） | 相談内容（本人／家族） | 各分野の特記、家族の介護の状況、援助の希望（p.7 の援助の希望は認知・精神の手助けの希望） |
| ある場面だけの思い（味が薄い、トイレは自分で行くのが当然） | その場面の特記 | 相談内容 |
| 本人の今の様子・気持ち（人に会いたくない、家事も仕事も手放す） | その分野の特記（この例は社会生活） | 援助の希望（手助けを頼む話ではない） |
| 病名・発症日・入院と転院・麻痺などの症状 | 既往歴・現症 | 生活の経過、基本動作の特記 |
| 言葉の障害の中身 | コミュニケーションの欄（言語障害） | 既往歴・現症 |
| 倒れる前の暮らし・仕事・付き合い | 生活の経過 | 社会生活の特記 |
| 医師の指示、服薬上の注意（出血） | 生活上配慮すべき課題 | 既往歴・現症 |
| 食事の中身（塩分の量、本人の不満、誰が作るか） | 食事の特記 | 既往歴・現症、生活上の注意、家族の介護の状況 |
| 家全体の造り（改築・段差・改修の要否） | 住居の特記 | — |
| 浴室の中の様子 | 入浴の特記 | 住居の特記 |
| 家の中をどう歩けるか | 基本動作の特記 | 住居の特記 |
| 誰が何を手伝うか（介護の分担） | 家族の介護の状況 | — |
| 専門職の助言 | 助言の目的の欄（ST の「人と話す機会を」→ コミュニケーション） | ほかの特記 |

- 選ぶ欄（チェック・丸）や表の欄（家族の一覧、受診状況）と、文章の欄が同じ中身になるのはよい。様式がそういう作りで、文章には理由や詳しいことを書く。ただし、選んだことをそのまま言い直すだけの文は書かない。
- 全体のまとめは要約が役目なので、ほかの欄の要点を短く言い直してよい。

**人が確かめる**: 4 人で分けて確かめる仕組みは [`../review/README.md`](../review/README.md)（2026-11-08）。

**見てもらいたいところ**（ケアマネの経験がある人に。`gold/sheet.json` の note に「要確認」とある 7 か所と、次の考え方）:

- 要介護認定の調査項目（1-x〜5-x）は、話から直接言えるものだけを正解にした。話に出ていない「4 群の行動はない」「聴力は普通」などは空が正解。
- 「援助の現状」（家族実施など）は、入院中の今の状況として空にした。退院後に嫁が担う予定のことは、家族の介護の状況（文章）に入れた。
- 嫁の名前（春子）は会話の中では出てこないが、原本の話者名から分かるものとして正解に入れた。
- 正解にない欄に、根拠のある文章を書いた場合は「余分」として数える（作り話とは分ける）。

### 正解をアセスメント用紙にする

```sh
python3 eval/bench/bench.py gold-data --gold eval/scenario/gold --out eval/scenario/gold/用紙
cd forms
for t in v1 v2; do
  node scripts/generate.mjs --form assessment --out ../eval/scenario/gold/用紙/アセスメント_$t.pdf ../eval/scenario/gold/用紙/アセスメント_$t.json
done
```

- 文章の欄は、正解の要点を「。」でつないだ文。人が書く文章より硬い。
- 同じ話が 2 つの欄に出ないように直したあとの版（上の「同じ話を 2 つの文章の欄に書かない」）。
- 値が 2 つ考えられる欄（`anyOf`。2-2 移動、2-4 食事摂取、食事の内容）は、最初の値を印字している。
- アセスメント実施日（初回）は話から取り出すものではなく、システムが持つ情報として、1 回目の日付（2021-01-21）を入れている。
- 図（家族構成図・人体図・見取図）は印字しない（pdfme の決まり）。

## 原本にするときに決めたこと（仮に置いたもの）

- **冒頭の経過表**: 1/20 までの行を、1 回目の「経過」（`s0`）にした。1/21 に MSW が経過を説明している（中身はシナリオに書かれていない）ので、その内容と、1/20 の嫁からの電話で分かったこととみなした。1/21 と 1/25 の行は、この面談と家屋調査そのものの説明なので入れていない。
- **家屋調査**: 誰の見立てかがシナリオに書かれていない（1 回目に PT・OT が「家屋調査で確認する」と言っていた）。記録した人はケアマネ（加藤）とした。
- **ト書き**: 加藤の「【以下について説明を行う】」の箇条書き、MSW の「経過の説明がある」、「一同（苦笑）」は発言ではないので、`kind: "ト書き"` にした。
- **入れていないもの**: 最後の「後日、居宅サービス計画の原案を持って訪問し、同意を得る。」（アセスメントの外）。
- **本文**: PDF の文字のまま。行の折り返しをつなぎ、英数字と日本語の間の空白（Word の表示で入ったもの）を取っただけ。「排便は 1～2 に 1 回」のような元の書き方も直していない。

## このシナリオで試せること

1. **途中のシートが育つか。** 1 回目のあとと 2 回目のあとで、シートがどう変わるか。
2. **「あとで確かめる」が閉じるか。** 1 回目に言われ、2 回目に答えが出る。
   - OT「段差は家屋調査の時に確認」（`s2-025`）→「手すりや段差解消などの住宅改修は必要ない」（`s3-004`）
   - PT「入浴は家屋調査の時に確認して提案」（`s2-046`）→「シャワーチェアを設置すれば、介助や見守りのもとで入浴できる」（`s3-003`）
3. **言っていることが人によって違うとき、両方残るか。**
   - 口の左側の残渣: ST「残ってしまうことがある」（`s2-031`）／本人「気にはならない」（`s2-050`）
   - むせ: NS「たまにある」（`s2-013`）／本人「どうってことない」（`s2-048`）
   - 同居: 嫁「主人は窮屈かもしれません」（`s2-059`）／長男「そんなことはない」（`s2-060`）
4. **話に出てこないことを書かないか。** 要介護度（結果の通知は届いているが、度数は出てこない）、年齢・生年月日、住所、経済状況、倒れる前の世帯（妻の有無、誰と住んでいたか）、娘の詳しいこと。どれもシートでは空のままが正しい。
5. **関係のない話から何も取り出さないか。** 病室の場面（`s1`）は、ほぼ制度と契約の説明。アセスメントの情報はほとんど出てこない。

## 確かめ方（評価）

一番大事なのは、**会話などの原本から必要な情報を取り出し、アセスメントシートに正しく書けているか**。なので、評価は**シート（3 層目）を主に**する。事実（2 層目）の評価は、シートが間違ったときに、どこで落ちたかを見分けるために使う。

### 正解を作る（人が作る）

| 正解 | 中身 | 使い道 |
|---|---|---|
| 正解のシート（3 層目） | アセスメントの欄ごとの正しい値と、その根拠の発言。**空のままが正しい欄も明示する** | 評価の本体 |
| 正解の事実一覧（2 層目） | シナリオから取り出せる事実。1 件 = 1 つの事実、23 項目の番号、誰が、元の発言の id | どこで落ちたかを見分ける |
| 正解の「確かめること」 | 1 回目のあとに残っているはずのこと（段差、入浴の方法、倒れる前の世帯など） | 未確認の扱いを見る |

- どれも、1 回目のあと（`v1` まで）と 2 回目のあと（`v2` まで）の 2 時点で作る。
- 正解のシートには判断が入る（例: 1-7 歩行を「何かにつかまればできる」とするか）。できれば、ケアマネの経験がある人に見てもらう。

### シート（3 層目）の判定

欄ごとに、次のどれかに分ける。

| 判定 | 意味 | 例 |
|---|---|---|
| 正しい | 正解と同じ値・中身 | 排尿: 日中 5〜6 回、夜間 1〜2 回、失禁なし |
| 誤り | 書いたが、値が違う | 麻痺を「右」と書く |
| 抜け | 話に出ていて書くべきなのに、空 | 服薬にワーファリンがない |
| 作り話 | 話に出ていないのに、書いた | 要介護度や年齢を書く |
| 根拠違い | 値は正しいが、根拠の事実・発言が違うか、ない | — |

- **選ぶ欄**（できる／できない、ない／ときどき／ある など）は、値が合っているかで判定する。
- **文章の欄**（特記事項、生活の経緯、課題分析など）は、正解に「入っているべき事実」を並べておく。それぞれが入っているか、正解にない中身が混ざっていないかで判定する。
- 数えるときは、「書くべき欄」（正解に値がある欄）でどれだけ正しいかと、「空のはずの欄」での作り話の数を分けて出す。空のはずの欄を正しいに数えると、良く見えすぎるため。作り話は 0 件を目指す。

### 事実（2 層目）で原因を見分ける

シートの「誤り」「抜け」ごとに、正しい事実が 2 層目にあったかを見る。

| 正しい事実が 2 層目に | どこで落ちたか | 例 |
|---|---|---|
| ない | 取り出し（原本 → 事実） | ST の発言から、口腔の話を取り出していない |
| ある | シートを書く段階（事実 → シート） | 事実はあるが、23 項目の番号の付け間違いで、その欄の絞り込みから外れた |

あわせて、2 層目にあるのにシートのどこにも使われず、「入れる欄がない」とも示されていない事実を数える（漏れ）。
